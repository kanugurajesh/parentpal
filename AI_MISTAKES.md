# AI mistakes log

A running log of places where AI-generated output (from the coding assistant that built this repo, or from the in-app LLM) was wrong, how it was caught, and what changed. Newest at the bottom. The point is to show the review process, not to make the AI look good.

| # | Phase | What the AI produced | How it was caught | Fix |
|---|---|---|---|---|
| 1 | 1 (content) | Five of the source URLs it first proposed were dead or wrong: the AAP sleep and "bedtime routines" pages had moved (404), the Ellyn Satter "Division of Responsibility" page 404'd, the JCSM article URL 404'd, and an NHS "healthy sleep tips for children" URL now **301-redirects to a different organisation's site** (The Sleep Charity). | Scripted `curl` status check of every candidate URL, then opened each page to confirm the title and that it actually says what the content claims. | Replaced with verified pages, recorded the exact page title and access date in `content/sources.json`, and dropped the Satter and NHS-sleep citations. The "parent decides what/when, child decides whether/how much" idea is now cited to the AAP picky-eater page, which states it directly. |
| 2 | 1 (content) | The first draft of the "When to talk to a professional" sections listed specific red flags (tantrums worsening after age 4, breath-holding until fainting; weight loss, gagging on textures) that **were not in any of the sources fetched**. They read as plausible clinical thresholds, which is exactly why they're dangerous. | Re-read each content claim against the fetched page summaries before seeding. | Rewrote both sections to only say what the AAP and NHS pages say ("if you're concerned about…, talk to your pediatrician / health visitor"). Rule added to `content/README.md`: no claim without a source in `sources.json`. |
| 3 | 1 (content) | The AASM sleep-duration ranges (12–16 h / 11–14 h / 10–13 h / 9–12 h) were written from the model's memory. The JCSM page couldn't be fetched (PubMed cookie wall, DOI redirect), so they are **not machine-verified**. | Flagged during source checking. | Kept, because they match the widely published consensus statement, but listed here and in the README limitations as **needs human verification** against the paper (doi:10.5664/jcsm.5866). |
| 4 | 5 (safety) | The rule-based safety classifier the AI wrote missed **"My husband slaps our son when he's angry and it leaves bruises"**. Its abuse rules knew "beats/punches/hits … with a belt" but not "slaps", and its child pattern knew "my son" but not "our son". The app then served *tantrum advice* for a child-abuse disclosure. | First run of `npm run eval` (case x3). | Added slap/smack/whip/burn + "leaves/left … bruises/marks" rules and widened the child pattern (`our/the/his/her son…`). Deliberately did **not** add "kicks"/"threw" (siblings kick each other daily, so that's tantrum territory). Regression tests added both ways. **Caveat:** x3 is now a seen case, so the safety score on this eval is optimistic. A held-out set is listed under future work. |
| 5 | 3 (retrieval) | Off-topic questions ("best stroller for a toddler?", "a children's book about dinosaurs") retrieved chunks at a score of ~0.44 because they shared generic words ("toddler", "best", "children", "book"), and the answer then **cited a sleep win as its source**. A citation that looks grounded but isn't is worse than none. | Eval case o1 returned `kind=answer` with 1 citation; inspected the top-3 scores by hand. | Removed generic parent words from the FTS query and added `MIN_CITABLE_SCORE` (0.4): below it, chunks aren't shown to the model or cited, so the answer says the topic isn't covered. A "dinosaur book" still matches the bedtime-book win at 0.44. That's documented as a known limit of lexical retrieval. |
| 6 | 5 (evals) | The AI's first grounding metric (lexical overlap between answer and cited chunks) reads **0.84–0.90 in mock mode** because the mock answer *is* stitched from chunk text. It's close to meaningless there. | Noticed while reading the first eval report. | Kept it (it's still useful with a real model) but labelled it in the report and README, and added an optional LLM-judge (`npm run eval -- --judge`) that only runs against a real provider. |
| 7 | Circles (guide reply) | The first version of the Circles "ParentPal guide" reply reused chat's citation threshold (0.4) and accepted chunks from any goal. In a test, a question that only loosely matched the library still drew a confident, cited guide reply that used a chunk from a **different goal**. An unprompted public answer that looks expert but isn't on topic is worse than silence. | Test "gives no guide answer when the library doesn't cover the question", then printed the retrieval scores by hand. | The guide now needs a confident top match (`CONFIDENT_SCORE`, 0.5) and only cites chunks from the circle's own goal. With a real model, an answer that cites nothing is dropped. Known limit: "which car seat brand fits a hatchback" still matches the tantrums car-seat win (0.80), because keyword retrieval can't tell a product question from a behaviour question. |
| 8 | Circles (moderation) | The AI's first mock harassment rule matched "bad mom / terrible mother" anywhere, so it would have **blocked a parent's own vent** ("I felt like a bad mom today"). Self-criticism is one of the main reasons parents post at all. | Caught reading the rule before running it. | Rules now match second person only ("you're a lazy parent"). The LLM prompt says self-criticism is allowed, and a Groq spot check of 10 replies agreed (vent: live; insult and shaming: rejected). Regression test added. |
| 9 | Circles (moderation) | Three regex slips in the same file. (a) Word boundaries `\b` written through a Python script turned into literal backspace characters, so the harassment rule **silently never matched**. (b) The email domain in "a.b@example.com" was also flagged as a "link". (c) A `/g` regex used with `.test()` keeps `lastIndex` between calls, which would make PII detection skip every other post. | (a) and (b) by failing unit tests; (c) on review. | Fixed all three, with tests for PII and harassment. |
